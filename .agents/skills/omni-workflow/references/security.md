# Omni security gates

Use for behavior that changes auth/identity, privileged messaging/permissions,
file trust boundaries or real academic mutations. Write a compact threat/authority
ExecPlan; obtain independent security review and executable negative-path evidence.

- Command/schema changes: trace relevant frontend callers, extension policy/router,
  shared adapter, server bridge protocol and desktop allowlists. Intentional
  unsupported adapters need not acquire fake parity.
- Writes: stale identity/context/baseline, invalid input, rejection, lost response,
  readback mismatch and partial success. Keep drafts until explicit Save;
  never blindly retry uncertain writes.
- Auth/session: logout/teacher/account switching, stale responses, second-tab
  invalidation, native login/challenge preservation. Never bypass protection.
- Previews: HTTPS/path/redirect validation, active content, MIME/bytes, credentials
  and desktop navigation/messages when relevant. No arbitrary URLs/scripts/endpoints.
- Async UI/protocol: worker BUSY serialization, cleanup/unmount, disabled transitions;
  concurrent mocked HTTP is not proof of worker behavior.
- Verify fixed data shapes; missing is not zero. Keep five-coin local allocation
  distinct from Omni authorization/balance; income estimates are not payroll.

Use fictional schema-faithful fixtures. Authorized live reads require narrow
account/context and redacted evidence; missing login is not permission to bypass it.
No real student mutations or secret logging in normal tests. FULL includes unit suite,
extension build and actual extension browser for relevant worker/UI/mutation changes.
One independent security reviewer may assess both threat and correctness evidence;
add another reviewer/tester only for a distinct uncovered risk, never formality.
