# Проверка Omni в браузере

Дата проверки: 15 сентября 2026 года (Europe/Moscow).

## Вывод

Собственный интерфейс технически реалистичен: действующий интерфейс на AngularJS получает данные отдельными HTTP-запросами. Для первого прототипа подходит расширение браузера, работающее на домене Omni с существующей сессией. Отдельному приложению потребуется дополнительно решить авторизацию и доступ к запросам; работа с другого домена не проверена.

## Что проверено

- После ручной проверки DDoS-Guard выполнен вход в отдельном профиле Edge.
- Открыты расписание, присутствующие, домашние задания, студенты и материалы.
- Просмотрены сетевые запросы и JavaScript действующего интерфейса.
- В текущем аккаунте раздел студентов показывает отсутствие групп, домашние задания — отсутствие работ. Переключение «Показать все группы» также не дало работ: `/homework/get-group-spec` ответил HTTP 200 с `null`.
- В разделе присутствующих нет текущей пары. «Прошлый период» открывает форму запроса доступа. Запрос не отправлялся.
- Оценки, посещаемость, материалы и работы не изменялись.

## Находки по задачам

### Копирование оценок

В `presentsCtrl.js`, функция `copyFromPrev`, отправляется запрос `/presents/copy-from-prev` с полем:

```js
only_attendance: $scope.result.scheduleType === 'planned'
```

Для запланированной пары интерфейс явно запрашивает копирование только посещаемости. Это возможное объяснение описанного поведения, а не воспроизведение ошибки на конкретном уроке. Правила сервера и поведение копирования после начала занятия пока не проверены. Простая подмена флага не является проверенным исправлением.

### Карточка ученика

В коде профиля используются `/students/get-details-stud`, `/students/get-stud-vizit`, `/students/get-comments`; параметр — `stud`. Это основа для подгрузки карточки при наведении или клике. Состав реальных ответов, доступность истории оценок и формула рейтинга не проверены: в доступных списках нет учеников.

### Отправленные материалы и ДЗ

Контроллер материалов уже вызывает `/presents/get-materials` с `group`, `lenta`, `date_vizit`. Контроллер выдачи ДЗ использует `/presents/get-homework` с `group`, `lenta`, `date`, `ospr`.

Следовательно, в существующем интерфейсе предусмотрена загрузка ранее выданного содержимого. Её можно сделать заметнее в новом интерфейсе. Фактические ответы для урока, детализация получателей и полнота истории не проверены.

### Предпросмотр домашних заданий

Шаблон `views/templates/homeworkStud.html` содержит текст ответа `answer_text` и действие для `download_url_stud`. Обработчик `downloadHomework` в `homeWorkCtrl.js` вызывает `window.open(url)`; встроенного просмотра вложения в этом шаблоне не найдено.

Для нового интерфейса можно добавить просмотр изображений, PDF и текстовых файлов. Потребуется проверить реальные ссылки, заголовки и доступность файлов. HTML и другой активный контент следует показывать изолированно; код учеников не запускать. Поддержку архивов и офисных форматов оценивать отдельно.

### Ошибки и потеря прогресса

В общем `httpInterceptor` из `/js/angular/script.js` обнаружены принудительные переходы:

- HTTP 403 → `/login/index`.
- HTTP 409 → `/auth/logout`; комментарий в коде связывает ответ с несовпадением пользователя страницы и текущей авторизации.

Общей перезагрузки при любой ошибке в этом обработчике нет. Конкретная ошибка пользователя не воспроизведена.

В новом интерфейсе нужны локальные черновики с привязкой к аккаунту, уроку и ученику, явный статус сохранения и сверка серверных данных перед повторной отправкой. После истечения сессии черновик должен восстанавливаться только для соответствующего аккаунта.
